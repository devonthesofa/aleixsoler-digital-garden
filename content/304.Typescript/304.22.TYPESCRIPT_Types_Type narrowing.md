_Type narrowing_, serveix per fer que TypeScript infereixi tipus més especifics segons el tipus. Quan treballem sobretot amb unions és quan té sentit el **type narrowing**. Com funciona:

Es posa un condicional([[304.22.TYPESCRIPT_Types_Type narrowing#Type Guard|Type Guard]]) fent un check del tipus, per exemple, si la `date` és un `string`. Si la condició és assertiva, aleshores **TypeScript pot inferir aquest `date` com a un tipus `string` a dins el condicional, i ens permtrà usar metodes i propietats que són permeses per un `string`**
### Type Guard
El type gaurd és un condicional que verifica que una variable sigui de un cert tipus, exemple:
```typescript
function getMarginLeft(margin: string | number) {  
  // margin may be a string or number here  
    
  if (typeof margin === 'string') {  
    // margin must be a string here  
  }  
}
```
Fent això a dins el condicional, TypeScript sap que margin és un string, i d'aquesta manera ens permetra usar methodes de string a la variable margin com per exemple:
```typescript
if (typeof margin === 'string') {  
  return margin.toLowerCase();  
}
```
Si cridessim aquesta funció fora del typeguard, el TypeScript ens petaria diguent que no existeix la funcio.

Aquest concepte es diu `type narrowing`(**Narrowing** is a TypeScript process that refines a value of multiple types into a single, specific type.) això és quan TypeScript descobreix quin tipus de variable pot ser en un degut moment del Codi.
### Narrowing with the `in` operator
Amb el condicional `typeof` per fer type narrowing podem arribar molt lluny, pero a mesura que tenim més tipus ens pot interessar saber si un mètode concret existeix a un tipus. Aquí és on entra l'[operador `in`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/in). Aquest operador verificar si una propietat existeix en un objecte o a dins del prototype chain, exemple:
```typescript
type Tennis = {
	serve: () => void;
}
type Soccer = {
	kick: () => void;
}
function play(sport: Tennis | Soccer) {
	if ('serve' in sport) {
		return sport.serve();
	}
	if ('kick' in sport) {
		return sport.kick();
	}
}
```

En aquest exemple, fer el check de si la propietat `'serve'` existeix a `sport`, si es així TypeScript pot fer narrow a dins el condicional, això funciona perque **TypeScript reconeix el `in` com a type guard**
### Narrowing with else
TypeScript reconeix el block `else` com a l'oposat type guard check de la sentencia `if`. Exemple:
```typescript
function formatPadding(padding: string | number) {
	if (typeof padding === 'string') {    
		return padding.toLowerCase();  
	} else {
	    return `${padding}px`;  
	}
}
```
En aquest cas, a dins del block `else` padding és un tipus number.

Com que TypeScript pot entendre com el nostre codi correrà en el runtime, és capaç d'inferir tipus especifics per nosaltres, com el cas de l'`else`
### Narrowing After a Type Guard
TypeScript és capaç d'nferir tipus sense la sentencia `else` si fem servir el `return`, mira l'exemple:
```typescript
type Tea = {
	steep: () => string;
}
type Coffee = {  
	pourOver: () => string;
} 
function brew(beverage: Coffee | Tea) {  
	if ('steep' in beverage) {   
		return beverage.steep();  
	}  
	return beverage.pourOver();
}
```

TypeScript infereix el tipus del segon `return` i sap que estem parlant d'un tipus `Coffee`

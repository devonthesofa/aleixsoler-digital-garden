En TypeScript no estém limitats a els pre-defined types, podem crear els tipus personalitzats per cubrir les nostres necessitats.

Aquest es poden fer servir de la mateixa manera que ho fem amb el tipus simples.

Un exemple super simples de custom type serien les [[./304.17.TYPESCRIPT_Types_Array type annotations#Tuples|304.17.TYPESCRIPT_Types_Array type annotations > Tuples]], però va molt més enllà, veiem-ho:

## Enums
Fem servir els `enum` quan volem `enum`erar tots els possibles valors que una variable pot tenir. Per exemple:

```typescript
enum Direction {
	North,
	South,
	East,
	West
}
```
Com es faria servir:
```typescript
let whichWayToArcticOcean: Direction;  
whichWayToArcticOcean = Direction.North; // No type error.  
whichWayToArcticOcean = Direction.Southeast; // Type error: Southeast is not a valid value for the Direction enum.  
whichWayToArcticOcean = West; // Wrong syntax, we must use Direction.West instead.
```

> Internament els enum es processen com a `numeros`, Els valors del Enums tenen assignat un valor numeric segons la posicio que tinguin, com si fos un array, el primer valor tindrà el 0, el segon 1...

Per tant, en l'exemple de sobre quan fem `whichWayToArcticOcean = Direction.North` el valor de ``whichWayToArcticOcean === 0`

Això vol dir que podriem reasignar `whichWayToArcticOcean` a `0,1,2,3` i no petaria, ja que internament són els possibles valor. **Atencio, podriem fer `whichWayToArcticOcean = 12321321` i no petaria**

Es pot modificar el numero de inici de la seguent manera:
```typescript
enum Direction {  
  North = 7,  
  South,  
  East,  
  West  
}
```
Ara seria igual a `7,8,9 i 10` respectivament

Si fos necessari, també es poden forçar els seus valors:
```typescript
enum Direction {  
  North = 8,  
  South = 2,  
  East = 6,  
  West = 4  
}
```
### String Enums vs Numeric Enums
> Resum: Sempre fer servir els `string enums`

TypeScript també ens permet fer `enums` basats amb `strings`, es defineixen molt similar:
```TypeScript
enum DirectionNumber { North, South, East, West }  
enum DirectionString { 
	North = 'NORTH',
	South = 'SOUTH',
	East = 'EAST',
	West = 'WEST'
}
```
Amb els `numeric enums`, els numeros poden ser assignats automàtcament, mentre que amb el `string enums` s'han de definir explicitament.

> La convenció per el valor dels `string enums` és posar com a valor el mateix posat com a key pero en majuscules. tècnicament podriem posar qualsevol cosa, però millor seguir la convenció, d'aquesta manera **els missatge de error i logs seràn més informatius**

**Es recomana sempre fer servir els `string enums` en comptes del numeric, ja que el `numeric enums` tenen comportaments que podrien portar bugs dificils de trobar** per exemple :
```typescript
let whichWayToAntarctica: DirectionNumber;  
whichWayToAntarctica = 1; // Valid TypeScript code.  
whichWayToAntarctica = DirectionNumber.South; // Valid, equivalent to the above line.
whichWayToAntarctica = 98765544; // Valid TypeScript code.  
```
**Els `string enums` són _molt_ més estrictes**, les variables no poden ser assignades a strings:
```typescript
let whichWayToAntarctica: DirectionString;  
whichWayToAntarctica = '\ (•◡•) /'; // Type error!  
whichWayToAntarctica = 'SOUTH'; // STILL a type error!  
whichWayToAntarctica = DirectionString.South; // The only allowable way to do this.
```
## Object Types
En aquest punt podem parlar sobre el `object-oriented programming` i com es relacionat amb TypeScript.
El `object types` són molt utils, ja que permeten definir a un nivell molt acurat les variables del nostre programa. Apart són els tipus més utilitzats, per tant s'han dentendre bé si volem entendre els codis d'altres programes

Aquí un exemple de com es defineixen, en aquest tipus definim el tipus duna persona:
```typescript
let aPerson: {
	name: string,
	age: number
};
```
El type annotation sembla un objecte literal, pero en comptes d'apareixer valors despres de la propietat, tenim tipus(**Qualsevol tipus, ja sigui enum, com un altre object type, com un number)**, aquí un exemple del control que ens proporciona:
```typescript
aPerson = {
	name: 'Aisle Nevertell', 
	age: "wouldn't you like to know"
}; // Type error: age property has the wrong type.
aPerson = {name: 'Kushim', yearsOld: 5000}; // Type error: no age property.
aPerson = {name: 'User McCodecad', age: 22}; // Valid code. 
```
## Type Aliases [^1]
Els _type aliases_ ens ajuden a personalitzar els tipus. Hi ha vegades que per conveniencia els posem un nom diferent

Fem servir el seguent format per fer-ho: `type <alias name> = <type>`:
```typescript
type MyString = string;
let myVar: MyString = 'Hi'; // Valid code.
```

Això es pot fer servir per qualsevol tipus. Són realment utils quan ens referim a tipus més complicats que es repeteixen varies vegades, especialment [[#Object Types]] i [[304.17.TYPESCRIPT_Types_Array type annotations#Tuples|tuples]].
Exemple:
```typescript
let aCompany: {
	companyName: string,
	boss: {
		name: string,
		age: number
	},
	employees: { 
		name: string,
		age: number 
	}[],
	employeeOfTheMonth: { 
		name: string, 
		age: number 
	},
	moneyEarned: number
};
```
En aquest cas de sobre hi ha molta repetició, per tant tenim una oportunitat per netejar-ho una mica amb type aliases:
```typescript
type Person = {
	name: string,
	age: number
};
let aCompany: {  
	companyName: string,
	boss: Person,
	employees: Person[],
	employeeOfTheMonth: Person,
	moneyEarned: number
  };
```

TypeScript aliases are nothing more than names. They have absolutely no influence over how types work. For example, the following code does not lead to type errors:
```typescript
type MyString = string;
type MyOtherString = string;
let firstString: MyString = 'test';
let secondString: MyOtherString = firstString; // Valid code.
```

The reason this works is that `MyString` and `MyOtherString` are not distinct types. They are just alternative names for the same thing.
## Function Types
Podem controlar els tipus de les funcions(arguments i retorn), fent servir _function types_. Exemple:
```typescript
type StringsToNumberFunction = (arg0: string, arg1: string) => number;
```
la sitaxis és igual que el **arrow notation**, pero en comptes de retornar un valor retornem un tipus, exemple d'us:
```typescript
let myFunc: StringsToNumberFunction;  
myFunc = function(firstName: string, lastName: string) {  
  return firstName.length + lastName.length;  
};  
  
myFunc = function(whatever: string, blah: string) {  
  return whatever.length - blah.length;  
};  

```
Com pots apreciar, no importa el nom del parametre en el type notation, mentre el tipus faci match, ja nhi ha prou.

Especte important, aquesta sintaxi no es correcte:
```typescript
type StringToNumberFunction = (string)=>number; // NO  
type StringToNumberFunction = arg: string=>number; // NO NO NO NO
```

## Generic Types
Els generics ens donen el poder de generar tipus reaprofitables, un exemple:
```typescript
type Family<T> = {  parents: [T, T], mate: T, children: T[]};
```

Aquest codi defineix una colleció d'objectes tipats, de diferents tipus per cada valor de `T`.
El generic `Family<T>`  no es pot fer servir com a type annotation, en comptes d'aixo s'ha de substituir la T amb algun tipus, per exemple `string`. Aleshores `Family<string>` és _exactament_ el mateix tipus d'objecte pero per `string`: `{parents:[string,string], mate:string, children: string[]}`

Per tant aquest assignament no contindrà errors:
```typescript
let aStringFamily: Family<string> = {
	parents: ['stern string', 'nice string'],
	mate: 'string next door',
	children: ['stringy', 'stringo', 'stringina', 'stringolio']
}; 
```

La `T` pot ser qualsevol cosa com `S` o `GenericType`, al final actua com si fos una "variable" que sobreescriure el lloc on es faci servir en el tipus generic

## Generic Functions
També podem usar els [[#Generic Types]] per les funcions, mira aquest exemple, podem definir una generic function que farà que es retorni un tipus array:

```typescript
function getFilledArray<T>(value: T, n: number): T[] {
	return Array(n).fill(value);
}
```
Aquest codi li diu a TypeScript que el `value` i el l'array retornat es del mateix tipus `T`. Per exemple `getFilledArray<string>('cheese', 3)`  farà que estigui correctament tipat, serà precisament equivalent a el type annotation `(value: string, n: number): string[]`

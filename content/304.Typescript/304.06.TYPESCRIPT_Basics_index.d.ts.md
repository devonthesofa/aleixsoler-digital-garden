> **`index.d.ts` és el punt d’entrada dels tipus d’un paquet.**
> No conté codi executable, només descriu **què exporta** una llibreria perquè TypeScript la pugui entendre.

## Què és un fitxer `.d.ts`

Un `.d.ts` és un **contracte de tipus**.

Defineix:
* tipus (`type`)
* interfícies (`interface`)
* signatures de funcions
* mòduls (`declare module`)

No defineix:
* lògica
* implementació
* comportament en runtime

Serveix perquè TypeScript pugui validar, documentar i donar IntelliSense **sense necessitat del codi font real**.
## Per què `index.d.ts`
`index.d.ts` no és especial per sintaxi, sinó per **convenció**:
* És el fitxer de tipus principal d’un paquet
* Normalment indicat al `package.json`
```json
{
  "main": "dist/index.js",
  "types": "dist/index.d.ts"
}
```
Quan algú importa el paquet:
```ts
import { myFunction } from "my-library";
```
TypeScript:
1. carrega `index.js` → runtime
2. carrega `index.d.ts` → tipus
## Exemple mínim d’`index.d.ts`
```ts
declare module "my-library" {
  export function myFunction(param: string): number;

  export interface MyInterface {
    property: string;
  }
}
```
Aquest fitxer defineix **què es pot importar** i **amb quins tipus**, però no diu com està implementat.
## Altres usos d’un `.d.ts`
### 1. Module augmentation
Permet **estendre tipus d’una llibreria existent** sense tocar el seu codi.
```ts
declare module "@mui/material/Button" {
  interface ButtonPropsColorOverrides {
    customColor: true;
  }
}
```
En alguns casos cal forçar la càrrega:
```ts
import type {} from "@mui/material";
```
### 2. Generació automàtica
Quan publiques una llibreria TypeScript, eines com `vite-plugin-dts` poden generar automàticament l’`index.d.ts` a partir del teu codi.

Això converteix el `.d.ts` en:
* contracte públic
* documentació
* garantia de compatibilitat
## Quan es carrega `index.d.ts`
### Càrrega automàtica (cas normal)
TypeScript el carrega automàticament si:
* el paquet és a `node_modules`
* el `package.json` té `"types"` o `"typings"`
* o existeix un paquet a `node_modules/@types`
No cal importar res manualment.
### Fora de `node_modules`
Si el `.d.ts` és teu (tipus personalitzats o augmentacions):
```json
{
  "compilerOptions": {
    "typeRoots": ["./types", "./node_modules/@types"]
  }
}
```

A partir d’aquí, TypeScript els carrega sols.
### Càrrega manual (excepcional)
Només en casos puntuals:
* proves ràpides
* configuracions incompletes
* augmentacions que no s’activen

Opcions:
```ts
/// <reference path="..." />
```
Si això és habitual → problema d’arquitectura de tipus.

## Globals vs mòduls (distinció clau)
* `.d.ts` **globals** (sense `export`)
  → s’apliquen a tot el projecte
* `.d.ts` **modulars** (`declare module`)
  → només s’apliquen si s’importa el mòdul
* `index.d.ts`
  → s’aplica quan s’importa el paquet

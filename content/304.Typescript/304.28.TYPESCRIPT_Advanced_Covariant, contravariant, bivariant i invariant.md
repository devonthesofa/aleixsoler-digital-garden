La variació en TypeScript especifica com un tipus genèric `F<T>` varia respecte el tipus T
## Covariant
- Imagina que tens una caixa on pots guardar coses, i la caixa és de tipus **Objecte**. Si aquesta caixa és **covariant**, podràs posar dins d'ella una cosa més concreta, com una **Camiseta**.
- Això vol dir que la caixa pot acceptar objectes més específics que el tipus que li vas dir al principi (en aquest cas, un **Objecte** pot contenir una **Camiseta**). És com si una caixa d'objectes pogués contenir una caixa més petita, com una de roba.

Covariant vol dir que:
- `Dog extends Animal` aleshores `Getter<Dog> extends Getter<Animal>`
Això vol dir que les propietats de Animal les trobes a Dog
## Contravariant
- Ara imagina que tens una caixa de tipus **Camiseta**, i vols posar dins una **Camiseta** o una cosa més general com un **Objecte**. Si aquesta caixa fos **contravariant**, podries posar dins qualsevol cosa més general, com un **Objecte**.
- Per tant, si tens una caixa que accepta només Camisetes, en el cas contravariant, acceptaria qualsevol cosa més general (com **Objecte**).
## Bivariant
- Una caixa **bivariant** accepta tant coses més concretes com coses més generals. És a dir, pots posar dins una **Camiseta** o un **Objecte** en funció del que necessitis.
- Això és un tipus de flexibilitat on la caixa pot gestionar tant els casos més específics com els més generals. Però, en alguns casos, pot generar problemes si no s'utilitza amb cura.
## Invariant
- Una caixa **invariant** és més estricta: només accepta exactament el que li has dit. Si la caixa diu que és per **Camisetes**, només hi pots posar una **Camiseta** i res més.
- És com una caixa amb una etiqueta que diu **Només Camisetes**. No hi pots posar ni **Objectes** ni cap altre tipus de cosa.
- Més info a [[./304.29.TYPESCRIPT_Advanced_Invariant|304.29.TYPESCRIPT_Advanced_Invariant]]

## La relació de variància
### De manera abstracta
La relació de variancia es podria definir de la seguent manera:
- **Covariant**: `F<T> extends F<U>`
- **Contravariant**: `F<U> extends F<T>`
- **Invariant**: Ni Covariant ni Contravariant, bàsicament `F<T>` sempre serà `F<T>` explícitament
- **Bivariant**: `F<T> extends F<U>` i `F<U> extends F<T>`
### En Typescript
Per entendre les relacions usarem les següents interfícies i tipus:
```typescript
interface Animal {
	animalStuff: any;
}
interface Dos extends Animal {
	dogStuff: any;
}

type Getter<T> = () => T; // Covariant
type Setter<T> = (value: T) => T; // Contravariant
type Inv<T> = (value: T) => T; // Invariant
```

## Tips Hacks Tools
```typescript
// Contravariant annotation
interface Consumer<in T> {
  consume: (arg: T) => void;
}
// Covariant annotation
interface Producer<out T> {
  make(): T;
}
// Invariant annotation
interface ProducerConsumer<in out T> {
  consume: (arg: T) => void;
  make(): T;
}
```

> **TypeScript construeix una “vista de tipus” del projecte abans de compilar.**
> Aquesta vista es crea seguint un **ordre de cerca determinista** per trobar declaracions de tipus.

## Visió global (model mental)
Quan TypeScript veu una referència a un tipus o a un `import`, es pregunta:

> “On puc trobar la declaració d’això?”

I segueix **aquest ordre**.

## 1. Fitxer actual i imports directes
Primer, TypeScript mira:
* tipus definits al mateix fitxer
* tipus importats explícitament

```ts
import { MyType } from "./my-types";
```

Si el tipus està aquí, **s’atura**.
## 2. Tipus locals del projecte (`include`)
Després, recorre **tots els fitxers inclosos al projecte** segons el `tsconfig.json`:
```json
{
  "include": ["src", "types"]
}
```
Això inclou:
* `.ts`, `.tsx`
* `.d.ts` globals
```ts
// types/global.d.ts
declare const API_URL: string;
```
Els globals **no necessiten import**.

## 3. `typeRoots`
Si existeix `typeRoots`, TypeScript **limita** on buscarà tipus globals:
```json
{
  "compilerOptions": {
    "typeRoots": ["./types", "./node_modules/@types"]
  }
}
```
Regla important:

> Si defineixes `typeRoots`, **TypeScript ignora qualsevol altre `.d.ts` global fora d’aquests paths**.

Això és una font clàssica de bugs.
## 4. Paquets instal·lats (`node_modules`)
Quan importes un paquet:
```ts
import { something } from "my-library";
```
TypeScript busca, en aquest ordre:
1. `"types"` o `"typings"` al `package.json`
2. `index.d.ts` al paquet
3. Paquet corresponent a `@types/my-library`

Si no troba res → error de tipus (tot i que el JS pot funcionar).
## 5. `@types` (DefinitelyTyped)
Per llibreries JS sense tipus:
```
node_modules/
  @types/
    react/
    lodash/
```
Aquestes definicions:
* es carreguen automàticament
* només si **no has restringit** `typeRoots`
## 6. Module augmentation
Quan existeixen múltiples declaracions pel mateix mòdul:
```ts
declare module "@mui/material/Button" {
  interface ButtonPropsColorOverrides {
    customColor: true;
  }
}
```
TypeScript:
* **fusiona** les declaracions
* no reemplaça, suma

_Però només si el mòdul base està carregat._
Per això a vegades cal:
```ts
import type {} from "@mui/material";
```
## 7. Globals vs mòduls
Distinció crítica:
* **Globals**
  `.d.ts` sense `import` / `export`
	- sempre disponibles (si estan dins `include` / `typeRoots`)
* **Mòduls**
  `.d.ts` amb `declare module`
	- només actius si el mòdul s’importa
## 8. `/// <reference path="..." />`
Això **força** TypeScript a carregar un fitxer de tipus **fora de l’ordre normal**.
* útil per proves
* no escalable
* senyal d’arquitectura dèbil si és habitual
## Ordre resumit
1. Fitxer actual + imports
2. Fitxers del projecte (`include`)
3. `typeRoots`
4. `node_modules` (`types`, `index.d.ts`)
5. `@types`
6. Augmentacions
7. References manuals (últim recurs)
## Símptomes típics i diagnòstic

| Símptoma                     | Probable causa                   |
| ---------------------------- | -------------------------------- |
| “Cannot find name”           | `.d.ts` fora d’`include`         |
| Tipus globals no visibles    | `typeRoots` mal configurat       |
| Augmentació no funciona      | mòdul base no carregat           |
| Funciona en JS però no en TS | falten tipus                     |
| Necessites molts `reference` | arquitectura de tipus incorrecta |
> **Quan TypeScript “no veu” un tipus, gairebé sempre és un problema de visibilitat, no de sintaxi.**

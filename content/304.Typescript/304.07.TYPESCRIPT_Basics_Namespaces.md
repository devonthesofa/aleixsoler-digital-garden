La feature de `namespaces` es va implemenetar abans que existis el `module encapsulation`. Aquest namespace es fa servir sobretot per declarar tipus propagats entre fitxers, com totes les declaracions que són globalment disponibles(window, document, navigator, i altres). [^1]
## Ordenar els tipus
Un dels usos del namespace és el de ordenar el tipus
### En un sol fitxer
crear un namespace `Validation` que després podrem fer servir fent `Validation.TipusExportat:
```typescript
namespace Validation {
  export interface StringValidator {
    isAcceptable(s: string): boolean;
  }
  const lettersRegexp = /^[A-Za-z]+$/;
  const numberRegexp = /^[0-9]+$/;
  export class LettersOnlyValidator implements StringValidator {
    isAcceptable(s: string) {
      return lettersRegexp.test(s);
    }
  }
  export class ZipCodeValidator implements StringValidator {
    isAcceptable(s: string) {
      return s.length === 5 && numberRegexp.test(s);
    }
  }
}
// Validators to use
let validators: { [s: string]: Validation.StringValidator } = {};
```
### En multiples fitxers
Els namespaces contribueixen entre ells, osigui es fan **merge**, per exemple:
#### fitxer1.ts
```typescript
namespace Validation {
  export interface StringValidator {
    isAcceptable(s: string): boolean;
  }
}
```
#### fitxer2.ts
Com que hi ha dependencies entre fitxer, ho indiquem amb el **reference tags** per dir-li al compilador sobre la relació entre fitxers
```typescript
/// <reference path="Validation.ts" />
namespace Validation {
  const lettersRegexp = /^[A-Za-z]+$/;
  export class LettersOnlyValidator implements StringValidator {
    isAcceptable(s: string) {
      return lettersRegexp.test(s);
    }
  }
}
```
#### Test.ts
```typescript
/// <reference path="Validation.ts" />
/// <reference path="LettersOnlyValidator.ts" />
/// <reference path="ZipCodeValidator.ts" />
// Some samples to try
let strings = ["Hello", "98052", "101"];
// Validators to use
let validators: { [s: string]: Validation.StringValidator } = {};
validators["ZIP code"] = new Validation.ZipCodeValidator();
validators["Letters only"] = new Validation.LettersOnlyValidator();
// Show whether each string passed each validator
for (let s of strings) {
  for (let name in validators) {
    console.log(
      `"${s}" - ${
        validators[name].isAcceptable(s) ? "matches" : "does not match"
      } ${name}`
    );
  }
}
```
## Simplificar el treball entre namespaces
Per crear noms més curts es poden crear **Alies** de la seguent manera
```typescript
namespace Shapes {
  export namespace Polygons {
    export class Triangle {}
    export class Square {}
  }
}
import polygons = Shapes.Polygons;
let sq = new polygons.Square(); // Same as 'new Shapes.Polygons.Square()'
```
## Treball amb llibreries externes
Per descriures els tipus de llibreries externes, osigui del npm, hem de declarar la API que exposa la llibereria. Com que les llibreries de JavaScript exposen un petit conjunt d'objectes al top-level, els namespaces encaixa bé per representar-los.

Li diguem [[304.05.TYPESCRIPT_Basics_Declare.md|declarations]] que no defineixen una implementació "ambient". Normalment aquests estan definits a els fitxers [[304.06.TYPESCRIPT_Basics_index.d.ts|.d.ts]].

Exemples:
### Ambient Namespaces
La llibreria de D3, defineix la seva funcionalitat en un objecte global anomenat `d3`. Com que questa llibreria es carregada amb el tag `<script>` en comptes del module loader, la seva declaració fa servir namespaces per definir el shape.
Per fer que el compilador de TypeScript detecti el shape, fem servir una **ambient namespace declaration**, exemple:
```typescript
declare namespace D3 {
  export interface Selectors {
    select: {
      (selector: string): Selection;
      (element: EventTarget): Selection;
    };
  }
  export interface Event {
    x: number;
    y: number;
  }
  export interface Base extends Selectors {
    event: Event;
  }
}
declare var d3: D3.Base;
```

El module augmentation serveix per poder, valga la redundància, augmentar les interficies i altres d'una tercer, ja sigui local, llibreria externa... Ve a ser un símil al [[prototype|prototype]].

## Module augmentation sintaxis
Augmentarem les interficies de [[MUI_material-ui|MUI_material-ui]], en aquest cas volem la property `color` del `Button` de material tingui un nou color `newCustomColorTest`
```jsx
import type {} from "@mui/material";
declare module '@mui/material/Button' {
  interface ButtonPropsColorOverrides {
    newCustomColorTest: true;
  }
}
```
Com pots apreciar a la primera linea hi ha un import que no es fa servir, si vols saber el motiu mira [[304.08.TYPESCRIPT_Basics_module_augmentation#Typescript module augmentation no reconegut|Typescript module augmentation no reconegut]], no fa falta aquest import si estas fent [[304.08.TYPESCRIPT_Basics_module_augmentation#Module augmentation en un projecte local|Module augmentation en un projecte local]]
## Typescript module augmentation no reconegut
Typescript no aplica el [[304.08.TYPESCRIPT_Basics_module_augmentation|304.08.TYPESCRIPT_Basics_module_augmentation]] si no s'ha importat el modul original.
S'ha d'assegurar que el modul original esta carregat perquè la augmentació funcioni, i tot-hi que que els [[./304.06.TYPESCRIPT_Basics_index.d.ts|304.06.TYPESCRIPT_Basics_index.d.ts]] es carreguen automàticament del `node_modules`, typescript tracta la augmentació com a isolated i no es linka en el modul original.
## Module augmentation en un projecte local
El cas més simple, s'ha de fer la augmentació com [[304.08.TYPESCRIPT_Basics_module_augmentation#Module augmentation sintaxis|Module augmentation sintaxis]]. I ja hauría de funcionar tot, ja que aquest cas [[304.08.TYPESCRIPT_Basics_module_augmentation#Typescript module augmentation no reconegut|Typescript module augmentation no reconegut]] no aplica, ja que com que és un projecte local les llibreries externes que vulguis augmentar ja estan carregades i conegudes per typescript, aleshores ja quedarà ben linkat
## Module augmentation per una llibreria
Una mica més enrevasat, ja que hem d'assegurar que el [[304.08.TYPESCRIPT_Basics_module_augmentation#Module augmentation sintaxis|Module augmentation sintaxis]] tingui els imports del modul original que es vol augmentar quan es fa la build, sino les llibreries consumidores no quedaràn exteses. Resumidament **l'index.d.ts de la dist ha de tenir els imports del modul que estas extenent**

### vite.config.ts
Aquest exemple és en [[Vite|Vite]], cal aplicar la seguent configuració en el dts:
```json
/// <reference types="vite/client" />
import { resolve } from 'node:path'
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import dts from 'vite-plugin-dts'

// https://vitejs.dev/config/
export default defineConfig({
  plugins: [react(), dts({
    rollupTypes: true,
    beforeWriteFile(filePath, content) {
      if (filePath.endsWith("index.d.ts")) {
        // INFO: Add custom import to ensure MUI types are included
        content = `import type {} from "@mui/material";\n${content}`;
      }
      return { filePath, content}
    }

  })],
  build: {
    lib: {
      entry: resolve(__dirname, './src/main.ts'),
      formats: ["es"]
    },
    rollupOptions: {
      external: ['react', 'react-dom', 'react/jsx-runtime', "@mui/material"],
      output: {
        globals: {
          react: 'React',
          'react-dom': 'ReactDOM',
          'react/jsx-runtime': 'react/jsx-runtime',
        },
      },
    },
    sourcemap: true,
    emptyOutDir: true,
  },
})
```
La important és el key `beforeWriteFile`. Això fa que s'afegeixi l'import a dalt de tot, ja que com que no es fa servir al fer [[treeshacking|treeshacking]] es borren els imports no fets servir, amb això assegurem que funcioni

## Module augmentation workaround 2(no probat)
If modifying the `index.d.ts` directly seems too complex, you can consider adding a `types.d.ts` file in your library and including it as a side file. Just make sure that the [[NODE_package.json|package.json]] includes a reference to it.

In short, the issue happens because TypeScript doesn’t pull in module augmentations unless the module is imported. By ensuring an import of `@mui/material` in the generated declaration files, you’ll solve this issue.

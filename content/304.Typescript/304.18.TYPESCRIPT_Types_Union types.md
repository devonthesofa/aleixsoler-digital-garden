> Les unions ens permeten fer que una variable accepti més d'un tipus

## Definir unions
Les unions ens permet definir multiples[[./304.17.TYPESCRIPT_Types_Array type annotations| tipus]] separant cada tipus amb una linea vertical `|`, exmeple:
```typescript
let ID: string | number;
// number  
ID = 1;  
// or string  
ID = '001';

function getMarginLeft(margin: string | number) {  
  return { 'marginLeft': margin };  
}
```

Fer servir unions ens dona més flexibilitat per definir tipus, pero hi ha un tema a considerar. Per exemple:
```typescript
function getMarginLeft(margin: string | number) {  
  // ...  
}
```
Com que margin pot ser `string` o `numero`, a la hora de treballar amb aquesta variable cal assegurar el tipus, perquè string pot tenir unes funcions i number un altre, per això cal implementar el que s'anomena un `type guard` [[./304.22.TYPESCRIPT_Types_Type narrowing#Type Guard|304.22.TYPESCRIPT_Types_Type narrowing > Type Guard]]
## Inferred Union Return Types
TypeScript sap inferir tipus en molts casos, això fa que no haguem d'escriure manualment els tipus, un dels casos de inferencia és el retorn de les funcions, si hi ha multipes possibles retons, **TypeScript inferira el tipus return type com a una unio de tipus**. Exemple
```typescript
function getBook() {  
  try {  
    return getBookFromServer();  
  } catch (error) {  
    return `Something went wrong: ${error}`;  
  }  
}
```
retornarà el tipus unit de `Book | string`

## Unions and Arrays
Les unions són encara més potents si les convinem amb arrays. Per crear una unio que suporta multiples tipus ho fem així, entre parèntesis `(string | number)` i amb la array notation `[]`, Exemple:

```typescript
const dateNumber = new Date().getTime(); // returns a number
const dateString = new Date().toString(); // returns a string
const timesList: (string | number)[] = [dateNumber, dateString];
```
Els parentesis son molt importats, si no els posesim representaria `string | number[]`

## Common Key Value Pairs
Quan posem **type member en una union, TypeScript ens permetrà usar el methodes i properitats que tinguin en comú**, per exemple:
```typescript
const batteryStatus: boolean | number = false;
batteryStatus.toString(); // No TypeScript
errorbatteryStatus.toFixed(2); // TypeScript error
```
Aquesta norma, també aplica per els type objects que definim nosaltres, exemple:
```typescript
type Goose = {
	isPettable: boolean;
	hasFeathers: boolean;
	canThwartAPicnic: boolean;
}
type Moose = {
	isPettable: boolean;
	hasHoofs: boolean;
}
const pettingZooAnimal: Goose | Moose = {
	isPettable: true 
};
console.log(pettingZooAnimal.isPettable); // No TypeScript error
console.log(pettingZooAnimal.hasHoofs); // TypeScript error
```

Qualsevol methodes o propietat que no esta compartida en els type members de les unions no serà permesa i tirarà un TypeScript error.
## Unions with Literal Types
Les unions de tipus literarls són utils quan volem crear estats, per exemple:
```typescript
type Color = 'green' | 'yellow' | 'red';
function changeLight(color: Color) {  // ...}
```

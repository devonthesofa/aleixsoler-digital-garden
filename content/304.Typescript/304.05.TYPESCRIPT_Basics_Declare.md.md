Per explicar-ho faré servir aquest exemple:

```ts
declare let demand1: Demand<unknown>;
```
## Idea clau
`declare` **no crea cap variable** ni genera codi JavaScript. Només li diu a TypeScript:

> “Això existirà en temps d’execució, confia en mi.”

És útil quan la definició real ve de fora (runtime, script extern, lib, tests, etc.).

## Desglossat del codi
1. **`declare`**
   Indica al compilador que la variable existeix, però **no la defineix**.
2. **`let demand1`**
   Nom de la variable.
3. **`Demand<unknown>`**
   Tipus de la variable: és un `Demand`, però el seu “contingut” és **desconegut** ([[./304.34.TYPESCRIPT_Types_unknown|unknown]]).
## Quan té sentit usar `declare`
Usa `declare` quan **necessites tipar una cosa que existeix fora del teu codi TS**.

Casos típics:
### 1) Variables globals externes
```ts
declare const API_URL: string;
```
### 2) Funcions globals / SDKs
```ts
declare function trackEvent(eventName: string, data: any): void;
```
### 3) Llibreries JS sense tipus (definir mòduls)
```ts
declare module "legacyLibrary" {
  export function legacyFunction(param: number): string;
}
```
### 4) Imports d’arxius estàtics (png, css, etc.)
```ts
declare module "*.png" {
  const value: string;
  export default value;
}
```
### 5) Extendre globals (`Window`, `Document`, etc.)
```ts
declare global {
  interface Window {
    myCustomProperty: string;
  }
}
```
### 6) Entorns de test
Normalment Jest ja ho resol amb `@types/jest`, però el patró és el mateix:
```ts
declare function describe(name: string, cb: () => void): void;
```

## On posar aquestes declaracions
### Recomanat (projectes reals): `.d.ts`

Crea una carpeta `types/` i posa-hi fitxers `.d.ts`:

```
types/
  global.d.ts
  assets.d.ts
  legacyLibrary.d.ts
```
I assegura’t que TypeScript els inclou:
```json
{
  "compilerOptions": {
    "typeRoots": ["./types", "./node_modules/@types"]
  },
  "include": ["src", "types"]
}
```

### Acceptable (temporal): al mateix fitxer
Útil per prototips, però evita-ho si creix.

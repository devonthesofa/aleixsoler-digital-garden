## `git rebase -i`

> [!NOTE] Important — `git rebase -i`
> El comandament `git rebase -i HEAD~N` permet **reescriure de manera interactiva l’historial dels últims N [[./303.10.GIT - El Commit i Conventional Commits|commits]]** de la [[./303.20.GIT - Conceptes Bàsics de Branca|branca]] actual.

Quan l’executes, s’obre un editor amb una llista de commits. Allà decideixes com es reapliquen:
- Reordenar commits (movent línies).
- Canviar el missatge (`reword`).
- Fusionar commits (`squash`, `fixup`).
- Eliminar commits (`drop` o esborrant la línia).
- Editar un commit antic (`edit`) per ajustar el contingut.
### Ús bàsic
```bash
git rebase -i HEAD~N
```
Exemple (últims 3 commits):
```bash
git rebase -i HEAD~3
```

### Conseqüència important
Un `rebase -i` **reescriu l’historial** i canvia els hashes dels commits afectats. Per això, si la branca ja era al [[./303.40.GIT - Treball en Remot i Push|remot]], un `git push` normal probablement fallarà i hauràs d’utilitzar el flux explicat a [[./303.40.GIT - Treball en Remot i Push|git push]] (normalment amb `--force-with-lease`).

### Si alguna cosa surt malament
Si el rebase et deixa la branca en un estat que no vols, el camí habitual és recuperar un estat anterior via [[./303.65.GIT - Reflog|git reflog]] i després tornar-hi amb [[./303.60.GIT - Reset|git reset]].

Exemple al usar el [[./303.65.GIT - Reflog|git reflog]]:
* Si veus que `HEAD@{3}` és "abans del rebase", aquell estat és una bona diana per tornar enrere.
### Quan **no** fer-ho

Evita `rebase -i` a branques compartides (`main`, `develop`, etc.) o quan altres persones ja han basat feina sobre aquests commits.

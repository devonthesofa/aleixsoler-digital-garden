# Traçabilitat de [[./303.10.GIT - El Commit i Conventional Commits|Commits]] i [[./303.40.GIT - Treball en Remot i Push|Pull]] Requests

Aquesta nota descriu com trobar la Pull Request o el commit original a GitHub/GitLab a partir del codi que tenim desplegat en un servidor, depenent de si s'han fet servir patches o no.

---

## Escenari 1: Desplegament amb Patches ([[./303.42.GIT - Aplicar PRs amb git am i rebase|git am]])
Si el desplegament s'ha fet seguint el mètode de [[./303.42.GIT - Aplicar PRs amb git am i rebase|aplicar PRs amb git am i rebase]], la traçabilitat és molt més senzilla perquè conservem la metadada del commit original.

### Passos:
1.  **Identifica la línia:** Fes un `git blame` del fitxer per veure quin commit va introduir el canvi.
2.  **Obté el Commit ID:** Copia el hash (ID) del commit que apareix al costat de la línia.
3.  **Consulta els detalls:** Pots fer un `git show <commit_id>` per veure el missatge sencer i els canvis associats.
4.  **Cerca a GitHub:** Copia el hash sencer o el títol del commit i enganxa'l al cercador del repositori a GitHub/GitLab. Això et portarà directament a la Pull Request original.

> [!TIP] **Dada clau**
> Si fas un `git show <commit_id>`, sovint trobaràs el número de la PR o l'autor original, la qual cosa facilita molt la feina de context.

---

## Escenari 2: Desplegament sense Patches
Si el codi s'ha pujat "a mà" o mitjançant un mètode que no conserva els hashes originals (com un [[./303.24.GIT - Merge i Mergetool|merge]] aixafat o una còpia directa de fitxers), el procés és més manual.

### Passos:
1.  **Fes el blame:** Igual que abans, obté el commit local.
2.  **Cerca per Hash (Fracàs):** En aquest cas, si busques el hash del commit local a GitHub, **no trobaràs res** perquè els identificadors no coincideixen.
3.  **Cerca per Text de Commit:**
    - Copia el títol o el missatge del commit (`git show`).
    - Busca aquest text a la pestanya de *Commits* de GitHub.
4.  **Cerca per codi:** Si el missatge tampoc coincideix (perquè es va canviar en fer el deploy), l'última opció és copiar una línia de codi molt específica i buscar-la directament al cercador de GitHub per veure en quines PRs apareix.

> [!WARNING] **Risc de pèrdua de context**
> En els desplegaments sense patches, la probabilitat de no trobar la font exacta és més alta. Per això es recomana sempre l'ús de `git am` per mantenir la història intacta.

---

## Comandes útils

| Comandament           | Utilitat                                                            |
| :-------------------- | :------------------------------------------------------------------ |
| `git blame <fitxer>`  | Veure qui i quan va modificar cada línia.                           |
| `git show <hash>`     | Veure el missatge complet i el contingut del commit.                |
| `git log -n 1 <hash>` | Veure només la capçalera del commit per copiar el títol ràpidament. |

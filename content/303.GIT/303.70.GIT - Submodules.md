# Git Submodules
Un **Submodule** és, essencialment, un repositori de Git dins d'un altre repositori de Git. Això permet mantenir un projecte (com una llibreria, un framework o un conjunt de configuracions) com una entitat separada, però integrada en el teu repositori principal.
## Per què utilitzar-los?
- **Componentització:** Pots separar el codi en mòduls independents.
- **Dependències externes:** Utilitzar llibreries de tercers de les quals vols mantenir el control de la versió exacta.
- **Compartir codi:** Diversos projectes "pare" poden apuntar al mateix repositori "fill".
## Comandaments Essencials
### 1. Afegir un Submodule
Per incloure un repositori extern al teu projecte:
```bash
git submodule add https://github.com/usuari/repo-llibreria.git carpeta-desti
```
*Això crearà un fitxer `.gitmodules` que registra el camí i la URL del submòdul.*
### 2. Clonar un projecte que té Submodules
Si fas un `git clone` normal, les carpetes dels submòduls estaran buides. Tens dues opcions:
- **Opció A (Automàtica):**
    ```bash
    git clone --recursive https://github.com/usuari/projecte-principal.git
    ```
- **Opció B (Manual, si ja has clonat):**
    ```bash
    git submodule update --[[303.04.GIT - Configuració i Inici|init]] --recursive
    ```
### 3. Actualitzar els Submodules
Si el repositori extern ha canviat i vols portar les noves actualitzacions al teu projecte pare:
```bash
git submodule update --[[303.40.GIT - Treball en Remot i Push|remote]] --[[303.24.GIT - Merge i Mergetool|merge]]
```
## Flux de treball (Working inside)
Treballar amb submòduls és una mica diferent de l'habitual perquè el projecte pare no guarda els fitxers del submòdul, sinó que guarda un **punter a un [[./303.10.GIT - El Commit i Conventional Commits|commit]] específic**.
1.  **Entra a la carpeta del submòdul:** `cd carpeta-desti`
2.  **Fes canvis i commit:** Com en qualsevol repo normal.
3.  **Puja els canvis del submòdul:** `git push`
4.  **Actualitza el pare:** Torna a la carpeta arrel del projecte principal i fes un commit del "punter" (el canvi de versió del submòdul).

> [!WARNING] **Compte amb el "Detached HEAD"**
> Per defecte, els submòduls solen estar en estat "Detached HEAD" (no apunten a cap [[./303.20.GIT - Conceptes Bàsics de Branca|branca]], sinó a un commit ID). Abans de programar dins d'un submòdul, assegura't de fer `[[303.22.GIT - Checkout|git checkout]] main` (o la branca que toqui).

## Limitacions i Consideracions

- **Complexitat:** Requereix que tot l'equip entengui com funcionen els submòduls per evitar carpetes buides o versions desactualitzades.
- **Commits oblidats:** Si fas un commit al projecte pare que apunta a un commit del submòdul que **no has pujat (push)** al servidor, els teus companys tindran un error en intentar actualitzar.
- **Alternatives:** En entorns de llenguatges específics, sol ser millor utilitzar gestors de paquets (NPM per a JS, Composer per a PHP, Cargo per a Rust), però els submòduls són imbatibles quan el codi és agnòstic o compartit entre llenguatges.

## Estructura de fitxers

Quan afegeixes un submòdul, el teu projecte es veu així:

```text
meu-projecte/
├── .git/
├── .gitmodules      <-- Configura les URLs i paths
├── src/
└── llibreria-externa/ <-- Punter al commit X del repo extern
```

# Git Tags
Els **Tags** (etiquetes) s'utilitzen per marcar punts específics en l'historial de Git com a importants. Normalment, es fan servir per marcar punts de llançament de versions (ex: `v1.0`, `v2.4.1`).
## Tipus de Tags
### 1. Tags Anotats (Recomanat)
Es guarden a la base de dades de Git com a [[./303.03.GIT - Terminologia i Objectes|objectes]] complets. Contenen el nom del creador, el correu electrònic, la data i tenen un missatge propi (com un [[./303.10.GIT - El Commit i Conventional Commits|commit]]).
```bash
git tag -a v1.0.0 -m "Versió estable de llançament"
```
### 2. Tags Lleugers (Lightweight)
Són simplement un punter a un commit específic (com una [[./303.20.GIT - Conceptes Bàsics de Branca|branca]] que no es mou). No contenen metadades addicionals.
```bash
git tag v1.0.0-lw
```

---

## Comandes Essencials

### Llistar tags
Per veure totes les etiquetes creades:
```bash
git tag
```
Per buscar un patró específic (ex: totes les de la sèrie 1.x):
```bash
git tag -l "v1.*"
```

### Veure informació d'un tag
Mostra les metadades de qui va fer el tag i el missatge de l'etiqueta:
```bash
git show v1.0.0
```

### Taguejar commits passats
Si se t'ha oblidat posar un tag en un commit anterior, pots fer-ho passant el hash:
```bash
git tag -a v0.9.0 <hash-del-commit>
```

## Compartir Tags ([[./303.40.GIT - Treball en Remot i Push|Push]])
Per defecte, `git push` no envia els tags al servidor remot. Cal fer-ho de forma explícita.

- **Enviar un tag específic:**
  ```bash
  git push origin v1.0.0
  ```
- **Enviar tots els tags locals que no estiguin al remot:**
  ```bash
  git push origin --tags
  ```

---

## Eliminar Tags

### 1. En local
```bash
git tag -d v1.0.0
```

### 2. Al servidor remot
```bash
git push origin --delete v1.0.0
```

## Bones pràctiques ([[GIT_versionamiento_semantico|SemVer]])
La majoria de projectes segueixen el **[[./303.12.GIT - Versionament Semàntic|Semantic Versioning]]** (Versionat Semàntic): `MAJOR.MINOR.PATCH`
* **MAJOR:** Canvis que trenquen la compatibilitat (breaking changes).
* **MINOR:** Noves funcionalitats sense trencar res.
* **PATCH:** Correcció d'errors (bug fixes).

> [!TIP] **Tags en el desplegament**
> En entorns de CI/CD, crear un tag sol ser el "trigger" (disparador) que activa automàticament el desplegament a producció.

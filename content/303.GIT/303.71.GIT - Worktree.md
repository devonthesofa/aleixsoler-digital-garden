# Git Worktree

**Git Worktree** és una funcionalitat de Git que permet tenir diversos directoris de treball (*working trees*) vinculats a un **únic repositori local**. A diferència d'un git clone tradicional, on només pots tenir una [[./303.20.GIT - Conceptes Bàsics de Branca|branca]] activa per directori, el worktree permet tenir múltiples branques "tretes" simultàniament en carpetes diferents sense duplicar les dades del repositori.
## Per què utilitzar-lo? (Casos d'ús)
Tradicionalment, per canviar de context (ex: un hotfix urgent a mig fer una feature), havies de fer `[[303.64.GIT - Stash|git stash]]` o un [[./303.10.GIT - El Commit i Conventional Commits|commit]] "brut". Amb worktrees, simplement canvies de carpeta.
- **Multitasca:** Pots executar tests en una branca mentre continues programant en una altra.
- **Col·laboració amb IA:** Ideal per a [[./303.53.GIT - Comparativa de Fluxos de Treball|fluxos de treball]] on diferents agents d'IA escriuen codi en branques separades simultàniament. Evites col·lisions de fitxers i pots esborrar el worktree en acabar.
- **Comparació fàcil:** Pots obrir dues carpetes al teu IDE (VS Code, Cursor, etc.) i comparar visualment o moure codi entre branques sense necessitat de fer *merges* constants.
- **Eficiència vs Clons:**  
	- **No duplica dades:** Comparteixen la mateixa carpeta `.git`.
	- **Actualització única:** Si fas un `git [[303.40.GIT - Treball en Remot i Push|fetch]]` en un worktree, els canvis apareixen a tots.
	- **Branques locals compartides:** No cal fer *push/pull* per veure una branca local d'un worktree a l'altre.
## Comandes Essencials
### 1. Afegir un nou directori de treball
Per crear una carpeta nova vinculada a una branca:
- **D'una branca existent:**
    ```bash
    git worktree add ../nom-carpeta nom-branca
    ```
- **Creant una branca nova:**
    ```bash
    git worktree add ../nom-carpeta -b nova-branca
    ```
- **Partint d'un punt específic (ex: `main`):**
    ```bash
    git worktree add ../nom-carpeta origin/main -b bug-fix
    ```
### 2. Llistar i Gestionar
- **Llistar actius:** `git worktree list` (mostra el path, el hash i la branca).
- **Eliminar un worktree:**
```bash
	git worktree remove ../nom-carpeta
```

> [!IMPORTANT]
> Si tens canvis sense commitejar, Git bloquejarà l'eliminació. Fes servir `--force` si vols descartar els canvis i borrar-lo igualment.
- **Neteja manual:** Si has esborrat la carpeta manualment des de l'explorador de fitxers:
    ```bash
    git worktree prune
    ```
## Com funciona per dins?
Dins d'un worktree secundari, no hi trobaràs una carpeta `.git`. En el seu lloc, hi ha un **fitxer `.git`** que conté un punter cap al directori `.git` del repositori original. Això permet que tots els comandaments de Git funcionin amb normalitat però compartint l'historial i la [[./303.04.GIT - Configuració i Inici|configuració]].
## Estructura de Treball Recomanada
Per evitar el desordre visual (tenir carpetes de worktrees barrejades amb altres projectes), es recomanen dues estratègies:
### Opció A: El mètode de la carpeta "Pare"
Crea una carpeta de projecte i fica-hi el "main" dins d'una subcarpeta (molts usen `_` o `main` per tenir-lo a dalt).

```text
projecte-X/
├── _/               <-- El teu "main" (working [[303.03.GIT - Terminologia i Objectes|tree]] principal)
├── feature-A/       <-- Worktree add ../feature-A
└── hotfix-1/        <-- Worktree add ../hotfix-1
```
### Opció B: [[./303.07.GIT - Bare Repository|Bare Repository]]
Configurar el repositori original com a `--bare`, de manera que totes les branques es gestionin com a worktrees al mateix nivell.
## Limitacions i "Gotchas"
- **Bloqueig de Branca:** No pots fer *check-out* de la mateixa branca en dos worktrees diferents alhora. Git ho prohibeix per evitar corrupció de dades.
    - *Error típic:* `fatal: 'main' is already checked out at...`
- **Espai en disc:** Tot i que l'historial es comparteix, cada worktree té els seus propis fitxers de codi i, sobretot, la seva pròpia carpeta de dependències (com `node_modules`). Això pot consumir molt espai ràpidament.
* **Submòduls:** La gestió de submòduls pot ser més complexa i pot requerir passos addicionals de sincronització.
* **Càrrega cognitiva:** Tenir massa carpetes obertes pot confondre sobre on s'estan fent els canvis. Es recomana esborrar el worktree tan bon punt s'acabi la tasca.

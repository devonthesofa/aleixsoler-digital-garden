## `git push` - opcions rellevants

### `git push` (per defecte)

> Envia els [[./303.10.GIT - El Commit i Conventional Commits|commits]] locals al repositori remot **sense reescriure l’historial**.

- Fallarà si l’historial remot ha avançat.
- És l’opció segura i recomanada en [[./303.20.GIT - Conceptes Bàsics de Branca|branques]] compartides.

És el comportament que **hauries d’utilitzar sempre per defecte**.

---

### `git push --force`

> Força l’enviament **sobreescrivint l’historial remot sense cap comprovació**.

* Elimina commits remots si no existeixen localment.
* Pot destruir treball d’altres persones sense avís.

> [!warning] Perillós
> **Altament perillós** en branques compartides.

Només acceptable en casos molt controlats o en repositoris personals.

---

### `git push --force-with-lease`

Si mai necessites forçar un `push`, **aquesta és l’opció recomanada**.

> [!NOTE] Important — `git push --force-with-lease`
> Hi ha situacions en què l’historial local d’una branca **no coincideix** amb el del repositori remot (per exemple, després de [[./303.62.GIT - Amend|reescriure commits]]).

En aquests casos, un `git push` normal fallarà i caldrà forçar l’enviament:

```bash
git push --force-with-lease
```

Aquest comandament permet sobreescriure l’historial remot **amb una comprovació prèvia de seguretat**:
- Git només farà el `push` si el contingut remot és el que tu esperes.
- Si algú altre ha fet canvis a la branca, l’operació fallarà i **no es perdrà cap feina**.

> *És una alternativa més segura que `git push --force`, ja que evita sobrescriure canvis d’altres persones sense adonar-te’n.*
#### Casos habituals on pot ser necessari
- Després d’un [[./303.26.GIT - Rebase|rebase]].
- Després de [[./303.62.GIT - Amend|reescriure commits]].
- Quan [[./303.60.GIT - Reset|neteges]] o [[./303.26.GIT - Rebase|reorganitzes]] l’historial d’una branca.
#### Quan **no** s’hauria d’utilitzar
- En branques compartides (`main`, `develop`, etc.).
- Si no tens clar si altres persones han treballat sobre la mateixa branca.
- Quan no entens per què necessites forçar el `push`.

---

### `git push --set-upstream`

> Defineix la branca remota per defecte per a la branca local.

```bash
git push --set-upstream origin nom-branca
git push -u origin nom-branca  # Sovint es veu com `-u`
```

- S’utilitza normalment **el primer cop que puges una branca nova**.
- Permet després fer simplement `git push` i `git pull`.

---

### `git push --tags`

> Envia totes les etiquetes locals al repositori remot.

- Els `tags` **no es pugen automàticament** amb un `push` normal.
- Útil per versions (`v1.2.0`, `release-2026-10`, etc.).

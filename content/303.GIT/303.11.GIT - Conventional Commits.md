## Missatges de commit - convencions i estils [^1][^2]

> [!NOTE] missatges de commit
> El missatge d’un commit descriu **què canvia** i **per què**, i és clau per entendre l’historial d’un projecte.
> Seguir una convenció fa l’historial **més llegible, més navegable i més útil** amb el temps.

No és obligatori, però en projectes mitjans o grans es nota
## Conveció habitual: Conventional Commits

Una de les convencions més esteses és l’anomenada [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/), basada en un prefix que indica el tipus de canvi.
### Format general

```text
<type>: descripció breu
```

Exemple:
```text
feat: afegeix login amb Google
```

## Tipus de commit més habituals

### `feat`

> Afegeix una funcionalitat nova per a l’usuari.

Exemples:
- `feat: afegeix sistema de notificacions`
- `feat: permet exportar dades a CSV`

### `fix`

> Corregeix un error.

Exemples:
- `fix: arregla validació de formulari`
- `fix: evita crash en carregar usuari`

### `chore`

> Tasques de manteniment que no afecten funcionalitat ni lògica principal.

Exemples:
- `chore: actualitza dependències`
- `chore: neteja scripts de build`

### `refactor`

> Canvi intern de codi sense afegir funcionalitat ni corregir errors.

Exemples:
- `refactor: simplifica lògica de permisos`
- `refactor: reorganitza serveis`

### `docs`

> Canvis només en documentació.

Exemples:
- `docs: afegeix guia d’instal·lació`
- `docs: corregeix errors tipogràfics`

### `test`

> Afegeix o modifica tests.

Exemples:
- `test: afegeix tests per al login`
- `test: millora cobertura de validacions`

### `style`

> Canvis de format (espais, lint, ordre d’imports) sense afectar el comportament.

Exemples:
- `style: aplica format del linter`
- `style: ordena imports`

### `build`

> Canvis en el sistema de build o dependències.

Exemples:
- `build: afegeix suport per Docker`
- `build: ajusta [[303.04.GIT - Configuració i Inici|configuració]] de Vite`

### `ci`

> Canvis en configuracions de CI/CD.

Exemples:
- `ci: afegeix pipeline de tests`
- `ci: ajusta workflow de [[303.80.GitHub - Plataforma i Flux|GitHub]] [[303.81.GitHub - Eines de Col·laboració|Actions]]`

## Scope (opcional)

Pots afegir un **àmbit** per concretar millor el canvi:

```text
feat(auth): afegeix login amb Google
fix(api): corregeix error 500 en login
```

## Altres estils de missatge (sense prefixos)

### Missatge descriptiu simple

```text
Afegeix suport per exportar dades
```

És més lliure però menys estructurat per automatització

### Format imperatiu (estil Git clàssic)

```text
Add support for data export
```

Molt habitual en projectes open-source

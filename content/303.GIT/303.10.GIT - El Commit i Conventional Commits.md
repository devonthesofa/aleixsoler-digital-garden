## `git commit` - confirmar canvis

> [!NOTE] Important — `git commit`
> El comandament `git commit` crea un **punt estable a l’historial** del repositori, capturant l’estat actual de l’índex (*[[./303.06.GIT - Estats dels Fitxers|staging area]]*).
> Un commit representa **una unitat lògica de canvi**.

Només es confirmen els fitxers que prèviament s’han afegit a l’índex amb `git add`.

## Ús bàsic

### Crear un commit

```bash
git commit
```

- Obre l’editor per escriure el missatge.
- El commit inclou **només** els canvis en staging.
### Crear un commit amb missatge directe

```bash
git commit -m "missatge del commit"
```

## Bones pràctiques del missatge
Un commit hauria de representar [[303.09.GIT_conventional commits|un canvi coherent]]
## Confirmar fitxers modificats sense passar per `git add`

```bash
git commit -a -m "missatge"
```

- Afegeix automàticament els fitxers **ja seguits**.
- **No** inclou fitxers nous.

Útil per canvis ràpids, però pot amagar què estàs confirmant.
## Veure què s’està a punt de confirmar

```bash
git status
```

```bash
[[303.31.GIT - Comparació amb Diff|git diff]] --staged
```

Comprova-ho sempre abans de fer `commit`.
## Cancel·lar un commit abans de fer `[[303.40.GIT - Treball en Remot i Push|push]]`

Si encara no has compartit el commit:
- Pots desfer-lo amb [[303.06.GIT_reset|git reset]]
- Pots ajustar-lo amb [[303.02.GIT_amend|git commit --amend]]

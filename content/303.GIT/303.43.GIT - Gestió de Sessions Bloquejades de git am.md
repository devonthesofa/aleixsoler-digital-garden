# Qui està bloquejant el repositori? (`[[303.42.GIT - Aplicar PRs amb git am i rebase|git am]]` session)

Si en intentar fer un desplegament o un canvi de [[./303.20.GIT - Conceptes Bàsics de Branca|branca]] et trobes amb el missatge d'error:
`The repository is in the middle of an am session!`
...significa que algú (o algun script de deploy) ha intentat aplicar un patch, ha tingut un conflicte i ha deixat la sessió oberta i bloquejada.

## Com descobrir el "responsable"
Per saber quina [[./303.40.GIT - Treball en Remot i Push|Pull]] Request s'estava intentant aplicar i qui és l'autor dels canvis, utilitza el següent comandament:
```bash
git am --show-current-patch
```

### Què ens diu aquesta informació?
Aquest comandament mostrarà el contingut del fitxer `.patch` que s'està intentant aplicar en aquest precís moment. Fixa't en aquestes línies:
  - **Subject:** Sol ser el títol de la [[./303.41.GIT - Traçabilitat de Commits i Pull Requests|Pull Request]] o del [[./303.10.GIT - El Commit i Conventional Commits|commit]]. Aquí veuràs de què va la feina.
  - **From:** El nom i l'email de la persona que va fer el commit original.
  - **Date:** Quan es va crear el canvi.

> [!TIP] Consulta ràpida
> Si només vols veure el missatge del commit sense tot el codi del patch, pots provar de mirar el fitxer intern de git (si tens curiositat):
> `cat .git/[[303.26.GIT - Rebase|rebase]]-apply/msg-clean`

-----

## Què fer per desbloquejar-lo?
Un cop ja saps qui és el "culpable" i de què va la PR, tens tres opcions segons el context:

1.  **Si vols cancel·lar-ho tot i deixar-ho com estava:**
    ```bash
    git am --abort
    ```
    *Això elimina la sessió de patch i et permet tornar a treballar.*
2.  **Si vols arreglar el conflicte tu mateix:**
    Resoldre els fitxers marcats, fer `git add` i després:
    ```bash
    git am --resolved
    ```

3.  **Si vols que el responsable ho arregli:**
    Avisa'l\! Ara ja saps qui és gràcies al `show-current-patch`.
